## Стек и окружение

Версия Python закреплена в `.python-version` (сейчас — та, что в файле), а не
в `requires-python`: `uv.lock` закрепляет пакеты, но не интерпретатор. Без
`.python-version` uv берёт любой установленный Python из диапазона
`requires-python`, а там, где Python нет (задача на HPC), скачивает самый
свежий — и ноутбук с задачей работают на разных версиях. Смена версии —
правка `.python-version` и `requires-python`, `uv lock`, коммит; на HPC
это новый venv.

Какие версии поддерживает каркас и почему — раздел «Environment» скилла
lightning-hydra.
{{/if}}

## Доступы

Логины, пароли и ключи лежат только в домашнем каталоге того, кто
запускает, с правами 600: на ноутбуке{{#if transport}} и в HPC-home{{/if}}. В репозиторий,
конфиги проекта, переменные окружения задач (`--env`) и аргументы команд
они не попадают. Конфиги проекта хранят только адреса и имена профилей.
Таблица доступов — в протоколе настройки доступов и в разделе «Доступы»
[`README.md`](../README.md).

1. Агент секреты не трогает: не открывает и не печатает файлы с ними, не
   передаёт значения в командах. Состояние доступов он узнаёт из проверок
   компонентов; если чего-то нет, показывает пользователю путь и секцию с
   плейсхолдерами, а заполняет её пользователь.

## Сообщения коммитов

Формат Conventional Commits. Заголовок — `тип(область): что сделано`:
по-английски, повелительное наклонение, со строчной буквы, без точки, не
длиннее 72 символов. Хук `commit-msg` в pre-commit проверяет заголовок.

| Тип | Когда |
|---|---|
| `feat` | новая возможность |
| `fix` | исправление |
| `perf` | ускорение без смены поведения |
| `refactor` | переделка без смены поведения |
| `test` | только тесты |
| `docs` | задачи, спайки, решения, эксперименты, соглашения без изменений кода |
| `build` | зависимости, сборка, `pyproject.toml` |
| `chore` | остальное: инструменты, pre-commit, чистка |

Область не обязательна. Коммит с кодом и документами получает тип по коду.
{{#if task-tracker}}
Задачи, которые коммит закрывает или заводит, перечисляются в скобках в
конце заголовка, с суффиксом: `feat(data): add loader (0006.jyn)`.
{{/if}}

## Прочие договорённости проекта

Скиллы агента ({{components}}) лежат в проекте, в `.agents/skills/`. Их
читают Codex, OpenCode, Cursor, Copilot и Gemini CLI. Для Claude Code в
`.claude/skills/` стоят относительные симлинки на те же каталоги. Версии
скиллов записаны в `skills.lock`. Скопированные скиллы не редактируются:
правка вносится в исходник скилла, затем скилл переустанавливается из корня
проекта и коммитится:

```bash
bash <исходник скилла>/install.sh --project
```

{{#if research-log}}
После обновления research-log запускается `upgrade.py`.
{{/if}}
{{#if task-tracker}}

research-log ведёт журнал в `docs/{hypotheses,experiments,technotes,findings,protocols,decisions}/`,
task-tracker — задачи в `docs/tasks/` и спецификации в `docs/specs/`. Связь
между ними одна: поле `motivated_by` эксперимента хранит id задачи.
{{/if}}
